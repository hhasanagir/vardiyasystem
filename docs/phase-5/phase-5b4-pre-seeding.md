# Phase 5B.4 — Pre-Seeding Architecture

## Problem

Phase 5B.2/5B.3 discovered that the greedy optimizer did NOT pre-seed existing assignments into the candidate. This caused:

1. Existing assignments not contributing to workload/fatigue/fairness calculations
2. The optimizer treating the schedule as empty even when partially filled
3. Hard constraint validation detecting false conflicts with existing assignments

## Solution

`GreedyOptimizationStrategy.generateCandidateWithPreSeeding()` implements a two-phase pipeline:

### Phase 1: Pre-Seed Existing Assignments

```
problem.existingAssignments.all
  → convert to CandidateAssignment (with isPreSeeded: true)
  → push to candidate.assignments
  → build workload, nightCount, consecutiveDays, lastShiftDate from existing
```

### Phase 2: Generate Only Unfilled Slots

```
for each day/month/device/shift:
  if slot already filled (existing) → skip
  if slot empty → find available personnel → select best → add new assignment
```

## Pre-Seeded Assignment Treatment

- **Pre-seeded assignments are IMMUTABLE** during optimization
- They are NOT re-validated against hard constraints (they were validated at creation time)
- They ARE included in soft constraint scoring (fairness, workload, fatigue)
- They ARE included in the final candidate and reported in the result

## CandidateAssignment.isPreSeeded Flag

- `true` → assignment was pre-seeded from existing schedule
- `false` (or undefined) → assignment was generated by optimizer
- Used by `evaluateHardConstraints` to skip pre-seeded assignments
- Used by `buildExplanations` to report pre-seeded vs new counts

## Backward Compatibility

- Existing `POST /api/v1/schedules/optimize/dry-run` API unchanged
- If no existing assignments → behavior identical to 5B.2
- If existing assignments provided → they are pre-seeded and preserved

## Files Changed

- `candidate-schedule.ts`: Added `isPreSeeded?: boolean` to `CandidateAssignment`
- `greedy-strategy.ts`: Rewritten to use `generateCandidateWithPreSeeding()`
- `optimization-result.ts`: Added `existingAssignments`, `newAssignments`, `scoreComponents` to summary
